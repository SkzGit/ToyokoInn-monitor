はじめに

このマニュアルは、ToyokoInn-monitor を初めて利用する方のための説明書です。

「Pythonを使ったことがない」
「GitHubをあまり知らない」
「VS Codeもあまり使ったことがない」

また、このシステムをしばらく使わなかった場合でも、このマニュアルを見れば運用を再開できることを目的としています。

困ったときは、後半の「トラブルシューティング」や「よくある質問」を参照してください。

システム概要

ToyokoInn-monitor は、東横INN公式サイトの空室状況を自動で監視するシステムです。

監視したいホテル、宿泊日、部屋タイプを登録しておくことで、空室が見つかった際に Discord へ通知します。

また、GitHub Actions を利用することで、パソコンの電源が入っていなくても定期的に監視を行うことができます。

さらに、ブラウザから設定を変更したり、GitHubへ変更内容を保存したりすることができます。

このシステムでできること

・複数ホテルの監視

・複数宿泊日の監視

・複数部屋タイプの監視

・空室が見つかったらDiscordへ通知

・監視履歴の表示

・ブラウザから設定変更

・設定の保存

・設定ファイルのエクスポート

・設定ファイルのインポート

・GUIからGitHubへ保存

・GitHub Actionsによる自動監視

必要な環境

このシステムを利用するためには、次のものが必要です。

【Windows】

Windows 10 または Windows 11

本システムは Windows 上で利用することを想定しています。

【Python】

Python は、このシステムを動かすためのソフトウェアです。

Python がインストールされていないとシステムを起動できません。

【Visual Studio Code（VS Code）】

VS Code はプログラムを開いたり編集したりするソフトです。

本システムでは、起動や設定変更などに利用します。

【Git】

Git は、プログラムや設定の変更履歴を管理するソフトです。

「GitHubへ保存」機能を利用するために必要です。

【GitHub】

GitHub はプログラムを保存するクラウドサービスです。

GitHub Actions を利用することで、自動監視を実現しています。

【Discord】

Discord は通知を受け取るためのサービスです。

空室が見つかると、指定したチャンネルへ通知されます。

第2章　システムを起動する
==========================================================
この章で行うこと

この章では、パソコンの電源を入れてから管理画面を表示するまでを説明します。

毎日最初に行う作業です。

1. パソコンの電源を入れる

パソコンの電源ボタンを押します。

Windowsが起動したら、通常どおりログインしてください。

2. インターネットに接続されていることを確認する

画面右下のネットワークアイコンを確認してください。

Wi-Fiまたは有線LANが接続されていれば問題ありません。

※GitHubへの保存やDiscord通知を利用するためには、インターネット接続が必要です。

3. Visual Studio Code（VS Code）を起動する

デスクトップまたはスタートメニューから

「Visual Studio Code」

を起動します。

青色のアイコンが目印です。

4. プロジェクトを開く

通常は前回開いていた状態で表示されます。

もし表示されていない場合は

「ファイル」

↓

「フォルダーを開く」

をクリックします。

ToyokoInn-monitor フォルダーを選択してください。

5. ターミナルを開く

画面上部の

「ターミナル」

↓

「新しいターミナル」

をクリックします。

画面下に黒い画面（PowerShell）が表示されます。

もし既にPowerShellが開いている場合は、そのままで構いません。

6. 現在のフォルダーを確認する

次のコマンドを入力します。

pwd

または

Get-Location

ToyokoInn-monitor フォルダーが表示されればOKです。

違う場所の場合は

cd "ToyokoInn-monitorのフォルダー"

で移動してください。

7. サーバーを起動する

次のコマンドを入力します。

python server.py

Enterキーを押します。

8. 起動を確認する

しばらくすると画面に

Running on http://localhost:5000

のような表示が出ます。

これが表示されれば正常に起動しています。

※表示内容はバージョンによって多少異なる場合があります。

9. ブラウザを開く

Google Chrome

または

Microsoft Edge

を起動します。

10. 管理画面を開く

アドレスバーへ

http://localhost:5000

と入力します。

Enterキーを押してください。

管理画面が表示されます。

11. 管理画面が表示されたら確認すること

次の内容を確認してください。

□ ホテル一覧が表示されている

□ 前回の設定が残っている

□ エラーが表示されていない

□ ボタンが押せる状態になっている

問題がなければ起動完了です。

起動時によくあるエラー
エラー1
python は内部コマンドまたは外部コマンド…
原因

Pythonがインストールされていない、または環境変数(PATH)が設定されていません。

対処

Pythonをインストールし、PATHを設定してください。

エラー2
Address already in use
原因

既に server.py が起動しています。

対処

新しく起動する必要はありません。

ブラウザで

http://localhost:5000

を開いてください。

それでも利用できない場合は、起動済みの server.py を終了してから再度起動してください。

エラー3
ModuleNotFoundError
原因

必要なライブラリがインストールされていません。

対処

次のコマンドを実行してください。

pip install -r requirements.txt
エラー4

ブラウザで

http://localhost:5000

を開いても表示されない

原因

server.py が起動していない可能性があります。

対処

VS Codeへ戻り、

python server.py

が正常に起動しているか確認してください。

□ VS Codeを起動した

□ ToyokoInn-monitor を開いた

□ ターミナルを開いた

□ python server.py を実行した

□ ブラウザで http://localhost:5000 を開いた

□ 管理画面が表示された

第3章　毎日の運用方法
==========================================================
この章で行うこと

この章では、管理画面を使用して

・設定の確認

・ホテルの追加・変更

・設定の保存

・GitHubへの保存

・監視開始

までの流れを説明します。

通常は、この章だけ読めば日常の運用ができます。

1. 管理画面を開く

ブラウザで

http://localhost:5000

を開きます。

管理画面が表示されます。

2. 現在の設定を確認する

最初に、現在登録されている監視条件を確認してください。

確認する内容

□ ホテル名

□ 宿泊日

□ 部屋タイプ

□ 不要な設定が残っていないか

毎回変更する必要はありません。

変更がなければ、そのまま監視を開始できます。

3. ホテルを追加する

新しいホテルを監視したい場合は、

「候補追加」

ボタンをクリックします。

新しい入力欄が追加されます。

必要な内容を入力してください。

入力例

ホテル名

東横INN 新潟駅前

宿泊日

2026/08/15

部屋タイプ

シングル

※実際には候補一覧から選択する項目があります。

4. 不要なホテルを削除する

監視が不要になったホテルは削除できます。

削除後は必ず保存してください。

※保存しないと次回起動時に元へ戻ります。

5. 設定を変更する

宿泊日や部屋タイプなどを変更できます。

変更後は必ず

「設定を保存」

を押してください。

6. 設定を保存する

画面の

「設定を保存」

ボタンをクリックします。

保存が完了すると、設定はパソコン内に保存されます。

まだGitHubには保存されていません。

7. GitHubへ保存する

設定を変更した場合は、

「GitHubへ保存」

ボタンをクリックしてください。

成功すると

GitHubへ保存しました。

と表示されます。

これでGitHubにも保存されます。

8. 変更がない場合

GitHubへ保存しても

変更はありませんでした。

と表示される場合があります。

これは異常ではありません。

前回保存した内容と同じため、保存する変更がなかったことを意味します。

9. 監視を開始する

設定の確認が終わったら

「監視開始」

ボタンをクリックします。

監視が始まります。

ログ画面に処理内容が表示されます。

10. 監視中に確認すること

ログ画面を確認してください。

正常であれば

・監視が開始された

・ホテル検索

・検索結果

などが表示されます。

エラーが表示されていないことを確認してください。

11. Discord通知を確認する

空室が見つかった場合は、

Discordに通知が届きます。

通知が届かない場合は、

第7章「トラブルシューティング」

を参照してください。

第4章　設定の管理方法
==========================================================
この章で行うこと

この章では、管理画面で行える設定操作について説明します。

・ホテルを追加する

・ホテルを削除する

・監視条件を変更する

・設定を保存する

・設定をバックアップする

・設定を復元する

・GitHubへ保存する

1. ホテルを追加する

新しいホテルを監視したい場合は、

「候補追加」

ボタンをクリックします。

新しい入力欄が追加されます。

ホテル名、宿泊日、部屋タイプなど、必要な項目を入力してください。

入力が終わったら、

「設定を保存」

をクリックします。

必要に応じて

「GitHubへ保存」

も実行してください。

2. ホテルを削除する

不要になったホテルは削除できます。

削除ボタンを押して削除してください。

削除しただけでは保存されません。

必ず

「設定を保存」

をクリックしてください。

その後、

「GitHubへ保存」

も行うことをおすすめします。

3. ホテルの並び順を変更する

ホテルはドラッグ＆ドロップで並び順を変更できます。

※ドラッグ＆ドロップとは、マウスで項目をクリックしたまま移動する操作です。

並び順を変更しただけでは保存されません。

必ず

「設定を保存」

↓

「GitHubへ保存」

を行ってください。

4. 宿泊日を変更する

宿泊日を変更したい場合は、

日付を修正してください。

変更後は

「設定を保存」

を押してください。

5. 部屋タイプを変更する

部屋タイプを変更したい場合は、

一覧から希望する部屋タイプを選択してください。

変更後は

「設定を保存」

を押してください。

6. 設定を保存する

画面の

「設定を保存」

ボタンをクリックします。

これで現在の設定がパソコン内に保存されます。

この操作だけではGitHubには保存されません。

7. GitHubへ保存する

設定の変更が終わったら、

「GitHubへ保存」

ボタンをクリックします。

正常に終了すると

「GitHubへ保存しました。」

と表示されます。

この操作により、GitHubにも最新の状態が保存されます。

8. 設定をバックアップする

設定をバックアップしたい場合は、

「設定をエクスポート」

をクリックします。

設定ファイルがダウンロードされます。

このファイルは大切に保管してください。

パソコンが故障した場合でも、このファイルがあれば設定を復元できます。

9. 設定を復元する

バックアップした設定を戻す場合は、

「設定をインポート」

をクリックします。

保存してある設定ファイルを選択してください。

読み込みが完了したら、

内容が正しく反映されていることを確認してください。

最後に

「設定を保存」

↓

「GitHubへ保存」

を行ってください。

10. おすすめの運用方法

設定を変更したときは、必ず次の順番で操作してください。

設定を変更

↓

設定を保存

↓

GitHubへ保存

この順番にすることで、

・ローカル

・GitHub

の両方が同じ状態になります。

やってはいけない操作
× 保存せずにブラウザを閉じる

変更内容は失われます。

必ず

「設定を保存」

を押してください。

× GitHubへ保存だけ実行する

現在のバージョンでは、

設定保存後に

GitHubへ保存

を行ってください。

× エクスポートした設定ファイルを削除する

バックアップがなくなります。

重要な設定ファイルなので、安全な場所へ保管してください。

× インポート後に内容を確認しない

誤った設定ファイルを読み込んでいる可能性があります。

ホテル一覧や宿泊日を確認してから保存してください。

第5章　GitHub・GitHub Actions・Discordの使い方
==========================================================
この章で行うこと

この章では、GitHubを利用した運用方法について説明します。

このシステムは、

・パソコンで動かす方法

と

・GitHub Actionsで自動監視する方法

の2つがあります。

通常は、GitHub Actionsでの運用をおすすめします。

1. GitHubとは？

GitHub（ギットハブ）は、プログラムや設定をインターネット上に保存するサービスです。

このシステムでは、

・プログラム

・設定

・変更履歴

を保存するために利用しています。

また、GitHub Actionsを使うことで、パソコンの電源が切れていても監視を続けることができます。

2. GitHub Actionsとは？

GitHub Actionsは、GitHubに組み込まれている自動実行機能です。

このシステムでは、

一定時間ごとに自動で監視を実行します。

つまり、

パソコンの電源を切っていても監視できます。

3. GitHubへ保存する理由

設定やプログラムを変更しただけでは、

GitHub Actionsは変更内容を知ることができません。

そのため、

変更した内容をGitHubへ保存する必要があります。

管理画面の

「GitHubへ保存」

ボタンを押すことで、

現在の内容をGitHubへ反映できます。

4. GitHubへ保存する手順

① 管理画面で設定を変更する

↓

② 「設定を保存」をクリックする

↓

③ 「GitHubへ保存」をクリックする

↓

④

「GitHubへ保存しました。」

と表示されれば成功です。

5. 「変更はありませんでした。」と表示された場合

これはエラーではありません。

前回保存した内容と同じため、

GitHubへ保存する内容がなかったことを意味します。

そのまま使用できます。

6. GitHubで変更を確認する

ブラウザでGitHubを開きます。

対象のリポジトリを開きます。

画面上部の

「Commits」

または

履歴

を開くと、

保存履歴を確認できます。

最新の日時になっていれば正常です。

7. GitHub Actionsが動いているか確認する

GitHubで

対象のリポジトリ

↓

Actions

をクリックします。

監視用Workflowを開いてください。

一覧が表示されます。

8. Actionsの見方

■ 緑色（✓）

正常終了

問題ありません。

■ 赤色（×）

エラーが発生しています。

ログを確認してください。

■ 黄色

実行中です。

終了するまで待ってください。

9. Actionsのログを見る

失敗した実行をクリックします。

処理一覧が表示されます。

失敗した項目をクリックすると、

エラーメッセージが表示されます。

内容を確認してください。

10. Discord通知とは？

Discordは、

空室が見つかったことを知らせるために使用しています。

通知先は、

DiscordのWebhookです。

Webhookとは、

指定したチャンネルへ自動でメッセージを送る仕組みです。

11. Discord通知を確認する

Discordを開きます。

通知用チャンネルを開いてください。

空室が見つかると、

通知が表示されます。

12. 通知が来ない場合

まず、

GitHub Actionsが成功しているか確認してください。

成功している場合は、

GitHub Secretsに登録した

DISCORD_WEBHOOK_URL

が正しいか確認してください。

13. GitHub Secretsとは？

GitHub Secretsとは、

パスワードやWebhook URLなど、

公開したくない情報を安全に保存する機能です。

このシステムでは、

Discord Webhook URLを登録しています。

14. Secretsを確認する方法

GitHubで

Settings

↓

Secrets and variables

↓

Actions

を開きます。

DISCORD_WEBHOOK_URL

が登録されていれば正常です。

15. やってはいけない操作
× GitHub Actionsを無効にする

監視が実行されなくなります。

× Secretsを削除する

Discord通知が送信できなくなります。

× GitHubへ保存しない

ローカルの変更がGitHub Actionsに反映されません。

× Actionsが赤くなっているのに放置する

監視が正常に行われていない可能性があります。

原因を確認してください。

□ GitHubへ保存できた

□ GitHubで履歴を確認できた

□ GitHub Actionsが緑色だった

□ Discord通知が届くことを確認した

□ DISCORD_WEBHOOK_URL が登録されている

python --version

http://localhost:5000

python server.py

第8章　よくある質問（FAQ）
==========================================================
この章について

この章では、利用者からよくある質問と回答をまとめています。

分からないことがあったら、まずこの章を確認してください。

Q1. パソコンの電源を切っても監視は続きますか？

A.

監視方法によって異なります。

ローカル監視

パソコンの電源を切ると停止します。

GitHub Actions

パソコンの電源を切っても監視は継続します。

Q2. ブラウザを閉じても監視は続きますか？

A.

ブラウザを閉じても、server.py が動いていればローカル監視は継続します。

ただし、ブラウザを再度開くには

http://localhost:5000

へアクセスしてください。

Q3. VS Codeを閉じても監視は続きますか？

A.

server.py が終了すればローカル監視は停止します。

通常は、Ctrl + Cで終了してからVS Codeを閉じてください。

Q4. 「設定を保存」と「GitHubへ保存」は何が違いますか？

A.

「設定を保存」

現在のパソコンに設定を保存します。

「GitHubへ保存」

GitHubにも保存します。

GitHub Actionsで最新設定を使用するためには、両方実行してください。

Q5. 「変更はありませんでした。」と表示されます。

A.

異常ではありません。

前回GitHubへ保存した内容と変更が無かったという意味です。

Q6. GitHubへ保存しなくても使えますか？

A.

はい。

ローカル監視だけなら利用できます。

ただし、

GitHub Actionsは最新設定になりません。

Q7. Discord通知が来ません。

A.

次の順番で確認してください。

① GitHub Actions

↓

② GitHub Secrets

↓

③ Discord Webhook

↓

④ ログ

Q8. 同じ空室は何回も通知されますか？

A.

いいえ。

同じ空室は重複通知しないようになっています。

Q9. ホテルはいくつ登録できますか？

A.

管理画面から複数登録できます。

ただし、登録数が多いほど監視時間が長くなる可能性があります。

Q10. 設定はどこに保存されますか？

A.

「設定を保存」を実行すると、ローカル環境に保存されます。

「GitHubへ保存」を実行すると、GitHubにも保存されます。

Q11. 設定を変更したらすぐ監視に反映されますか？

A.

ローカル監視では、設定保存後に反映されます。

GitHub Actionsでは、「GitHubへ保存」後の内容が反映されます。

Q12. GitHubへ保存した設定は元に戻せますか？

A.

GitHubの履歴（コミット）から過去の状態を確認できます。

復元方法はGitの操作が必要です。

Q13. GitHub Actionsはどれくらいの間隔で監視しますか？

A.

GitHub Actionsのワークフローで設定された間隔で実行されます。

変更したい場合は、ワークフローファイルを編集してください。

Q14. Discord以外へ通知できますか？

A.

現在のバージョンではDiscord通知のみ対応しています。

Q15. エクスポートした設定ファイルは何に使いますか？

A.

設定のバックアップです。

新しいパソコンへ移行するときや、設定を元に戻したいときに利用できます。

Q16. GitHubへ保存した後にもう一度「設定を保存」は必要ですか？

A.

いいえ。

「設定を保存」を行った後に「GitHubへ保存」を実行していれば十分です。

Q17. 起動するたびに設定を入力する必要がありますか？

A.

いいえ。

保存した設定は次回起動時にも読み込まれます。

Q18. GitHub Actionsが赤くなっています。

A.

処理中にエラーが発生しています。

Actions画面からログを確認してください。

Q19. エラーが出たら最初に何を確認すればいいですか？

A.

次の順番がおすすめです。

エラーメッセージ

↓

server.py

↓

GitHubへ保存

↓

GitHub Actions

↓

Discord
Q20. 分からないことがあったら？

A.

まず、このマニュアルの

「第7章 トラブルシューティング」

を確認してください。

それでも解決しない場合は、

次の情報を記録してください。

・何をしたか

・何が表示されたか

・いつ発生したか

・GitHub Actionsの状態

・Discord通知の有無

これらの情報があると、原因を調査しやすくなります。

緑色のチェック（✓）が並んでいれば正常です。

万が一設定を誤って変更した場合でも、バックアップから復元できます。

□ GitHub Actionsが成功する

□ Discord通知が正常に届く

9. このシステムで特に注意すること

このシステムでは、次の3つが特に重要です。

① 「設定を保存」を忘れない

設定を変更しただけでは保存されません。

必ず「設定を保存」を実行してください。

② 「GitHubへ保存」を忘れない

GitHubへ保存しないと、GitHub Actionsでは古い設定が使用されます。

③ GitHub Actionsを定期的に確認する

GitHub Actionsが失敗していると、自動監視は行われません。

少なくとも週に1回程度は、Actions画面を確認することをおすすめします。
